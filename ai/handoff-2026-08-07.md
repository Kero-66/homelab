## Root cause: this session started with

A Russian-audio anime release (`Tsuihou Sareta Tensei Juu Kishi... AAC Rus`) got auto-grabbed by Sonarr via RSS from Nyaa.si/Prowlarr. Root cause: Sonarr v4's per-series language profile system is deprecated/non-enforcing for known languages (only still blocks the `Unknown` case, confirmed via a separate VOTOMS finding), and no custom format was scoring against parsed release language. Fixed by adding TRaSH's `Language: Not Original` CF (see "What's committed" above). Fully verified via Sonarr's parse API against real releases (JP-only, dual-audio, and the original bad release) — no regressions.

**Side finding along the way**: this Mac's Wi-Fi had IPv6 set to "Automatic," silently picking up the router's SLAAC-advertised DNS resolver alongside AdGuard — this is why `.home` domains intermittently failed to resolve in shell sessions. Fixed by the user setting IPv6 to "Link-local only" in System Settings. Not a repo change, but worth knowing if `.home` resolution issues recur on this machine.

## Missing-episodes investigation (todo #89 in `ai/todo.md` — has the full details, not duplicated here)

31 monitored series have missing episodes. Four were diagnosed in depth this session, revealing **three distinct root-cause patterns** — do not assume one fix applies broadly to the rest:

1. **Unparseable pack releases** (VOTOMS, Armitage III) — release title has no episode markers at all. Fixed via one-time manual override grab (see PATTERNS.md). Not a persistent fix — the next unparseable release for these shows needs the same treatment again.
2. **TVDB season-split mismatch** (GetBackers) — release group numbers continuously (`S01E01`-`S01E49`), TVDB split it into two artificial seasons. Needs a **persistent** scene-numbering fix (`sceneSeasonNumber`/`sceneEpisodeNumber` per episode + `useSceneNumbering: true`) — **proposed but not yet applied**, needs explicit user confirmation before bulk-writing episode metadata (the auto-mode classifier will block an unattended bulk write anyway). No XEM community mapping exists for this show (checked, confirmed absent), and XEM registration is closed, so this has to be done manually.
3. **Genuine content scarcity** (Trigun, Robotech S2) — the source that worked before is still active but specific episodes/seasons aren't currently indexed or have aged out of usenet retention. Not a config bug. Possible next step: check if missing content exists as a season/batch pack (more likely to still be in retention) rather than individual episode posts.

**Two corrected wrong assumptions during this investigation** (see `feedback_verify_before_asserting.md`): Robotech's episode gap has nothing to do with its real-world production history (user corrected this directly), and `Treasure Maps(SceneNZB)` is not anime-exclusive — it carries standard Western scene TV releases too (proven via Robotech's own grab history).

## What NOT to do

- Don't retry PUT-ing `/api/v3/languageprofile/1` — confirmed dead/non-persisting endpoint.
- Don't hit `sonarr.home/api/v3/...` directly for POST/PUT requests — use the `/sonarr/`-prefixed path directly to avoid the redirect silently dropping the request body.
- Don't `jq`-print or `cat` the `guid` or `.data.downloadUrl` fields from Sonarr release/history API responses — they embed a live Prowlarr API key.
- Don't add `/etc/hosts` entries or otherwise route around DNS resolution issues — explicitly forbidden by the user this session.
- Don't state explanations as fact (show production history, indexer capabilities, etc.) without checking actual data first — got corrected twice on this in the missing-episodes investigation.
