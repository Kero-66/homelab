## Gotchas hit this session, worth knowing before continuing

- **`infisical secrets get` needs `--projectId` and `--domain` explicitly** — without them it fails with "run infisical init" even when logged in. Pattern: `infisical secrets get <KEY> --env dev --path <PATH> --plain --projectId "5086c25c-310d-4cfb-9e2c-24d1fa92c152" --domain http://192.168.20.22:8081`. This is already documented in `ai/PATTERNS.md` — don't skip it out of habit.
- **qBittorrent direct-IP access (192.168.20.22:8085) returns 403** — use `http://qbittorrent.home` (via Caddy) instead, per `ai/PATTERNS.md`.
- **`ssh-add -` piping a key from a variable can silently fail** ("Identity added" doesn't print, `ssh-add -l` shows "no identities") — write the key to a temp file with `chmod 600` and `ssh-add <file>` instead, more reliable.
- **Sonarr's `manualimport` endpoint with a `seriesId` hint can silently drop unmatched files** rather than listing them — always cross-check the count/contents against a scan without the hint if something looks short.
- **Single-file torrents often get renamed on disk vs. the torrent's own name** — when Manual Import's folder scan comes up empty, check `content_path` via qBittorrent's API for the real filename before assuming the scan is broken.
- **A batch AskUserQuestion approval across many items is not a substitute for per-item confirmation before grabbing** — the user was explicit about this. Check monitoring-pattern signals (see the new standing rule above) and confirm before acting, not after.
