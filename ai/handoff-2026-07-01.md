### Current blocker: Logging suppressed at level 0

When `PUT /api/series/issues/{id}/queue` is triggered, it returns **Internal Server Error**. Comicarr logs show:

```
Logging level in config over-ridden by startup value. Logging level set to : 0
```

The override path in `config.py:683`:
```python
if comicarr.LOG_LEVEL is not None:
    log_level = comicarr.LOG_LEVEL  # overrides config's log_level=1 with 0
```

`comicarr.LOG_LEVEL` is set to 0 by the **logger quiet-mode check** in `logger.py`:
```python
LOG_LANG = localeinfo[0]  # reads system locale
if not LOG_LANG.startswith("en"):
    comicarr.LOG_LEVEL = 0  # quiet mode
```

Despite `LANG=en_US.UTF-8` being set in the container environment, `LOG_LANG` is still being set to something non-English (likely `"C"` or `"C.UTF-8"` from Python's `locale.getdefaultlocale()`). The fix of setting LANG env var hasn't solved it yet — Python may not pick up `LANG` via `getdefaultlocale()` on this container image.

### The actual crash (separate from logging)

The `queue_issue` endpoint crashes with:
```
UnboundLocalError: cannot access local variable 'booktype' where it is not associated with a value
  File "/opt/comicarr/comicarr/search.py", line ~2705
```

This is a **Comicarr bug**: when an exception occurs in `searchforissue()` before `booktype` is assigned (inside the large try block), the except handler itself crashes trying to reference `booktype` in the `except_line` dict. The real original exception is hidden.

We have NOT yet seen the original exception that triggers the except block.

## Immediate Next Steps

### 1. Fix the logging so we can see the real error

The LANG env var approach didn't work. Better fix: patch `logger.py` inside the container to hardcode `LOG_LANG = "en_US"`:

```bash
# Find the exact line
sudo docker exec comicarr grep -n 'LOG_LANG = language\|LOG_LANG = localeinfo' /opt/comicarr/comicarr/logger.py

# Patch it (use docker exec, NOT direct overlay editing — that causes stale file handles)
sudo docker exec -u root comicarr sed -i 's/^LOG_LANG = language$/LOG_LANG = "en_US"  # patched/' /opt/comicarr/comicarr/logger.py

# Delete the pyc via docker exec (creates whiteout, hides lower-layer pyc)
sudo docker exec -u root comicarr find /opt/comicarr/comicarr/__pycache__ -name 'logger*.pyc' -delete
```

Then restart (NOT recreate) the container via Dockhand restart API:
```bash
curl -b cookies.txt -X POST "http://192.168.20.22:30328/api/containers/{CONTAINER_ID}/restart?env=1"
```

### 2. Once logging works, find the real original exception

Trigger a search:
```bash
# Login to get cookie, then:
curl -b cookie -X PUT "http://comicarr.home/api/series/issues/246008/queue" \
  -H "X-Requested-With: ComicarrFrontend"

# Check logs immediately:
sudo docker logs comicarr --since=30s 2>&1 | grep -v 'GET /api\|GET /assets'
```

The real exception will now be visible. Common candidates:
- `comic["ComicName_Filesafe"]` is None and causes AttributeError downstream
- Some other column access failure before `booktype = comic["Type"]`

### 3. Fix the root exception in search.py

Once identified, patch `searchforissue()` to handle it. Also add `booktype = None` as a sentinel at the top of the try block (after `SEARCHLOCK.acquire()`) so the except handler doesn't also crash:

```python
# After comicarr.SEARCHLOCK.acquire():
booktype = None  # sentinel — prevents UnboundLocalError in except handler
```

## Infrastructure Notes

- **Dockhand API** (for container lifecycle):
  - Login: `POST /api/auth/login` with `{"username": ..., "password": ..., "provider": "local"}`
  - Restart: `POST /api/containers/{id}/restart?env=1`
  - Deploy/recreate: `PUT /api/stacks/{name}/compose` then `POST /api/stacks/{name}/deploy?env=1` with `{"forceRecreate": true}`
  - **WARNING**: `forceRecreate` in Dockhand didn't actually recreate (container creation date unchanged). Had to use `docker compose -f ... up -d --force-recreate` directly.
  - Dockhand's compose file: `/mnt/.ix-apps/app_mounts/dockhand/data/stacks/comicarr/compose.yaml`

- **Container overlay FS gotcha**: NEVER edit files directly in the overlay `diff/` directory from outside the container. It causes stale file handle errors and the merged filesystem doesn't pick up changes. Always use `docker exec` or `docker cp`.

- **Networks**: TrueNAS Dockhand-external networks are named `ix-arr-stack_default` and `ix-downloaders_default` (not `arr-stack_default` / `downloaders_default`).

- **Comicarr config categories**: Newznab categories in config.ini use commas to separate multiple values within a provider entry (`7030,7020`), but `#` is used as separator within the `extra_newznabs` field between providers.

- **Issue IssueID for testing**: `246008` = Initial D Vol 1 Issue 1 (Status=Wanted, ComicID=36842)
